# ChatGPT 网页通道修复：发送确认与结果读取

> 现象：ChatGPT 网页模式经常卡在「等待」，最后报「ChatGPT 未能确认发送」；偶尔发出去了，模型却说看不到图片；读回来的内容也对不上。

修复产物仍是 `patch/app-patched.asar`（16,089,861 字节），已在本机用真实 ChatGPT 会话从「报错」跑到「正常出结果」。

---

## 一、三个真实根因（都由实测 DOM 定位，不是猜的）

### 1. 页面偶发「无法加载 ChatGPT 模型」，composer 永久不可发送

连上桥接用的 Chrome（CDP）抓现场：

```
modelText: "无法加载 ChatGPT 模型"   modelDisabled: true   sendDisabled: true
```

模型选择器加载失败时，发送按钮跟着永久禁用。应用当时只是点一下、发现点不动，然后**空转 30 秒**报「未能确认发送」。

**验证可恢复**：CDP `Page.reload` 之后，同一个页面变成
`modelText: "GPT-6.1 Sol … Max Ultra"`，按钮恢复可用。→ 这是可自愈的瞬时状态。

### 2. 附件计数把会话里已有的图也算进去了

原来的判据是 `form img, [data-testid*="attachment"] img, main img` —— `main img` 把历史对话里的图、头像都数进来，附件还没传完就「够数」返回。于是消息发出去可能**不带图**，模型只能看到文字。

### 3. ChatGPT 换了会话 DOM，读结果的选择器整条失效

实测这一版页面：

| 选择器 | 命中数 |
|---|---|
| `[data-message-author-role]` | **0** |
| `[data-testid^="conversation-turn"]` | **0** |
| `article` | **0** |
| `[class*="MarkdownRoot"]` | 1（助手回答） |

用户附件也不再在用户气泡里，而是会话主区里一张 `img[alt="用户附件"]`（`blob:` 源）。所以 `#latestResponse` 找不到节点、`#waitForResponse` 只能等到超时。

## 二、改了什么（`electron/chatgpt-web.mjs`）

| 位置 | 改动 |
|---|---|
| 新增 `#composerHealth` | 读模型按钮文案/禁用态、发送按钮可用性；读不到返回 unknown，不误判 |
| 新增 `#reloadPage` / `#ensureComposerHealthy` | 模型列表明确坏掉时自动刷新，最多两次；仍失败给出可照做的报错 |
| `#submit` | 进入阶段后先做一次 composer 健康自愈，再选模式/模型/上传 |
| `#send` | 点之前先等发送按钮真正可用（≤12s）；模型列表坏掉直接报明确原因，不再空转 30s |
| `#waitForUploadedFiles` → `#composerAttachments` | 只统计 composer 范围内（附件卡片 / blob 缩略图），并要求**没有上传进度条**、连续两拍稳定 |
| 新增 `#assertComposerAttachments` | 发送前再确认附件数量没少，少了就停止发送并说明 |
| 新增 `#assertSentAttachments` | 发送后确认会话里确实出现了图片（按新版 DOM 统计），否则明确报「模型只看得到文字」 |
| `#latestResponse` | 加兜底：没有 role 属性时取 `main` 里最后一个 `MarkdownRoot`，并排除侧栏 |
| `#waitForResponse` | 完成判定不再强依赖「回答已完成」文案：有标记立刻收，没有就看停止按钮消失 + 正文稳定（工作模式多稳一拍） |

错误文案也改成能照做的：

- 模型没加载 → 「ChatGPT 页面的模型列表没有加载出来（常见于网络中断或登录过期）…请点『重跑』，或到网页窗口刷新后重试」
- 附件没跟上 → 「消息已经发出，但这一轮没有带上图片附件…请点『重跑』重新提交」

| 轮次 | 结果 |

## 四、还没覆盖到的

1. **模型列表加载失败的恢复路径没有在故障态下跑完整回合**：我是先把它刷新好、再验证正常回合。故障态只验证了「能识别 + 刷新后恢复」。
2. **`MarkdownRoot` 兜底是启发式**：已限制在 `main` 内并排除 `aside/nav/*sidebar*`，但如果 ChatGPT 再改类名，仍需跟版；好在失败会报「没有抓取到 ChatGPT 网页回复」，不会静默产出错内容。
3. **多图附件只验证到「至少有一张图随消息发出」**：会话里只渲染出一张可见缩略图，其余两张是否进入上下文没有逐一核对（模型描述里没提第三张参考图）。
4. 这些修改落在 `chatgpt-web.mjs`（主进程代码），和之前的细化功能改动在同一个 asar 里，**互不影响**：前者改 `electron/`，后者改 `dist/assets/index-*.js`。
