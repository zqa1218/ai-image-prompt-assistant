## 三、这次跑出来的三个问题

### 1. `[cite: N]` 角标泄漏进最终 Prompt（高优先级，可复现）

最终 Prompt 正文和「复制全文」拿到内容里，满是 `[cite: 1]`、`[cite: 1, 2]`、`[cite: 1, 3]`：

```
… 手持大型镰刀武器的骨架造型与持握受力[cite: 1]；保持底图原有低角度拍摄视角、焦段透视与画幅比例[cite: 1]。
将背景虚化区域替换为古典殿堂空间：… 边缘轮廓光[cite: 1, 2]。 …
```

这与应用自己的规则直接冲突——「最终 Prompt 不得出现 REFERENCE、参考图、图片编号、"与某图一致"或任何来源说明」，也与它自己生成的 QA 清单第 2 条冲突：

> 是否将所有参考图来源信息转换为纯画面视觉与材质描述，完全隐去了 REFERENCE 与图号字样 ← 而同一页的 Prompt 里还带着图号角标

前端 bundle 里我只找到剥离 `REFERENCE_n` / `参考图n` 的正则，**没有剥离 `[cite: N]` 的兜底**。建议在生成阶段输出的解析处加 `replace(/\[cite:[^\]]*\]/g, '')`，并在「复制全文 / 导出 .md / 导出 .json」前再兜一层。

### 2. 网页通道的 token / 缓存指标恒为 0，指标形同虚设

每次阶段完成，页脚都是 `输入 0（缓存命中 0，0%）· 输出 0`。原因是服务端对网页通道固定返回：

```js
usage: { prompt_tokens: 0, completion_tokens: 0, total_tokens: 0 }
```

而"前缀缓存是否命中"恰恰是这个项目最精心设计的东西（资产页展示了前缀哈希）。现在这个数字永远为 0，用户无法据此判断缓存到底有没有生效，反而容易误以为缓存失效。建议网页通道要么不显示这两项，要么用字符数/前缀哈希做粗略提示。

### 3. 阶段 2 计了 2 次调用，原因未定位

页脚计数：阶段 2 结束 `2 次调用` → 阶段 3 结束 `3 次` → 细化不动 `3 次` → 生成结束 `4 次`。即"原图分析"这一阶段消耗了 2 次模型调用，其余阶段各 1 次。

我确认过这 2 次里没有我误触的请求（第一次点击坐标偏了、没触发；探测接口当时返回 200 说明无请求在飞）。可能是该阶段内部设计成了两次调用，也可能是首次调用失败后的静默重试。若是后者，属于用户不可见的行为，建议在页脚或日志里显式记一行原因。
