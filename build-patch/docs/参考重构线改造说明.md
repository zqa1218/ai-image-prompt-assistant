## 一、① 已完成的改动

### 问题

原来 MJ 这条线的 compose 输出是一整段 `prompt`，正负混在一起、还常带中文说明或「以下是…」这类前后缀，复制出去要手工再拆。

### 改法（三处）

| # | 位置 | 改动 |
|---|---|---|
| E10 | `gu(e)` 的 compose 分支 | `mj-prompt-en` 走**独立契约**：只输出 `{"sections":[{"key":"正面提示词","body":…},{"key":"负面提示词","body":…}],"params":[…],"channel":…,"checklist":[…],"prompt":…}`，并明确禁止中文、禁止「Midjourney 提示词 / Prompt: / 以下是」前缀、禁止结尾追加说明，参数只写 `--` 项单独放 `params` |
| E11 | compose 结果解析 | 把 `sections` 拼成 `【正面提示词】…【负面提示词】…` 写进 `prompt` |
| E12 | compose 的 zod schema `ru` | 加 `sections` 字段——**这一步不做就白干**：zod 默认丢掉未知字段，`sections` 会在解析阶段被剥掉 |

E11 之所以拼 `【标题】`，是因为前端的分段显示器 `Rd` 并不读 `artifact.sections`，而是用 `Fd(prompt)` 按 **`【标题】`（≥2 个标记才分段，标题 1–16 字）** 把正文切开，每块配一个「复制这段」。顺着它来，才不用改 UI。

![MJ 正负分块](shots/mj-sections.png)

### 真机验证（参考重构线 · 存档「MJ 测试（胶片棚拍）」· Gemini Flash）

```
正面提示词  [复制这段]
a young East Asian woman with platinum blonde short hair, calm and cold expression, kneeling
posture on both knees on the floor … 85mm portrait lens

负面提示词  [复制这段]
scythe, weapon, prop, anime, 3d render, plastic smooth skin, harsh flash, exhibition hall,
messy background, white bokeh circles, oversaturated, deformed fingers, extra limbs, digital noise

参数
--ar 3:4   --v 6.0   --style raw   --stylize 150
```

- 正文是纯英文、无任何前后缀
- 正负两块各自有「复制这段」，可以分别粘贴
- 参数单独一栏，不混进正文
- 「复制全文」仍可用（会带上 `【正面提示词】` 标题，按块复制则不带头）

## 二、② 需求拆解

目标（原话）：在接收阶段的**上传原图下面**加一块资料收集（角色名 + 出处作品）→ AI 结合原图与资料收集信息、并给出包含下方参数与选项的合成灵感方案 → 生成后可直接「载入」，**跳过其余填写直接到方向建议**；最好还能顺手找参考图。

拆开是四件事：

1. 两个输入框（角色名称、出自哪个作品）
2. 一个「让 AI 收集资料并给方案」按钮 + 结果卡片
3. 「载入」按钮：把方案里的字段写回 intake，并把 `stageIndex` 直接推到「方向建议」并触发该阶段
4. 参考图检索（可选）

## 三、② 的实现路径（已定位到具体钩子）

这些是我这次读代码时确认可用的位置，落地时基本照抄即可：

| 要做的事 | 挂在哪 | 依据 |
|---|---|---|
| 两个输入框 | `gc.stages[intake].fields` 数组**开头**插入 `{key:'characterName',label:'角色名称',kind:'text'}` 和 `{key:'sourceWork',label:'出自作品',kind:'text'}` | 字段是数据驱动的，插进数组就渲染；放数组开头即出现在「上传原图」下面（原图/参考图在字段之前渲染） |
| 研究按钮 + 结果卡 | 接收组件 `Ad`（`case 'intake': (0,B.jsx)(Ad,{…})`） | 和之前改 `Wd`（细化）同样的手法：整体替换组件，加一个面板 |
| 调模型拿方案 | 复用 `detail` 通道 + focus 哨兵（和「待定项清单」完全同构）：新增 provider 方法 `askResearch`，`Ru(e,'detail','【资料收集】')`，在 `gu` 的 detail 分支再加一个前置判断返回 strict JSON | E1/E2 已经证明这条链路稳定（22–34 秒出合法 JSON） |
| 写回 + 跳阶段 | store 新增 `applyResearch(payload)`：`e({intake:{…merged}})`，然后 `e({stageIndex: 方向建议下标})` 并调用该作用域里的阶段运行器 `r(index)`（`advance()` 里就是 `await r(a)`） | 直接改 intake 会让「已启用的专项规则」重新计算，符合预期 |
| 参考图检索 | **不建议做自动下载**：ChatGPT 的图片搜索没有稳定的可抓接口，网页端拿图还要处理鉴权与外链；MVP 建议让模型输出「检索关键词 + 该找什么样的图」清单，用户自己搜 | — |

方案 JSON 建议形状（和现有 `sections`/`items` 风格一致）：

```json
{
  "character": {"name":"…","work":"…","origin":"游戏/动画/…","canon":["官方设定要点…"]},
  "inspiration": [{"title":"方案名","why":"为什么适合这个角色","how":"画面怎么改","params":["--ar 3:4","--stylize 250"]}],
  "fill": {"requirement":"可直接写入出图需求的整句","referenceRole":"只借气质","usage":"个人创作","outputSize":"原图尺寸"},
  "searchKeywords": ["角色名 官方立绘","角色名 服装设定集"]
}
```

「载入」= `fill` 写回 intake + 采用 `inspiration[0].params` + 跳方向建议；方案卡上可以逐条「用这个方案」。
