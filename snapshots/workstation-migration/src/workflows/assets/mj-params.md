# Midjourney 提示词组装与参数决策

## 一、提示词结构

```text
<主体与描述性限定> + <行为或事件> + <环境> + <构图与机位> + <光线> +
<材质> + <成像机制：白平衡/曝光/反差/景深/颗粒> + <技术参数>
```

规则：

- 用完整句子描述，不用关键词堆砌
- 主体直接命名（「红色雨伞的女人」），避免代词
- 具体到颜色、材质、光线设置、镜头与空间关系
- 不写「artistic」「make it better」这类无法执行的要求

## 二、参数矩阵

| 参数 | 用途 | 取值建议 |
| --- | --- | --- |
| `--ar` | 画幅比例 | 按交付用途写死，如 `3:4`、`16:9` |
| `--stylize` | 风格化强度 | 低（贴近提示词）100 左右；高（模型自由发挥）600~1000 |
| `--chaos` | 结果多样性 | 探索期 20~40；定稿期 0 |
| `--style raw` | 减少默认美化 | 写实、纪实、商品向时加 |
| `--no` | 负面排除 | 只排除真正会出问题的元素 |
| `--sref` | 风格参考 | 只借视觉处理，不借内容 |
| `--cref` + `--cw` | 角色参考（旧版） | 需要跨图保持同一人物时 |
| Omni Reference | 人物或物件一致性 | 与之互斥，一张图只承担一个职责 |

## 三、参考图分工铁律

**一张参考图只承担一个职责**：

- 内容与构图 → Image Prompt
- 视觉处理 → Style Reference
- 人物或物件一致性 → Omni Reference

同一张图被指派两个职责时，必须拆分或明确优先级。

## 四、迭代纪律

- 先用 Draft / Conversational 模式试方向，锁定后再正式出图
- **每轮只改一个变量**，否则无法归因
- 新一轮以原始参考图为基准重新编译，不把上一轮生成图当成新的视觉输入

## 五、合规边界（必须转述给用户）

Midjourney 官方不提供 API，其条款禁止自动化工具访问、交互或生成，社区指引也说明不提供授权第三方脚本。

因此本程序**只准备提示词、参数矩阵与提交前 QA 清单**，由账号本人手动在官网或 Discord 界面提交。
不要把按钮、斜杠命令、参数、任务 ID 或图片 URL 表述成某个 REST 接口、SDK、webhook 或环境变量。

## 六、提交前 QA 清单

- 提示词里主体是否被直接命名，没有代词歧义
- 光线是否写清了来源与方向
- 参数是否与交付用途一致（比例、风格化强度）
- 参考图职责是否唯一
- 是否包含 `--no` 需要排除的项
- 是否已说明由用户本人提交，程序不代为操作
