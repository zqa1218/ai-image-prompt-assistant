# MJ / Banana 工作台完整改造计划

制定日期：2026-11-12。先完成版本基线修正，再按以下顺序实施。本文区分“计划能力”和“已实现能力”；实际进度见 `docs/progress.md`。没有写入进度的能力不视为完成。

## 一、整体目标与边界

将 MJStudio 的任务/结果处理、Prompt Wizard 的提示词工作流、Photoshop 的素材读取与结果回传整合成一个本地创作工作台。完整链路是：

`需求与 PS/本地素材 → 提示词生成或手工输入 → 人工确认快照 → MJ 官网 / Banana API → 结果归档选图 → 文件导出 / PS 回传`

两条图像通道严格分离：

| 通道 | 工作台负责 | 用户/外部负责 | 禁止混用 |
|---|---|---|---|
| MJ 官网协作 | 输入、角色化参考图、参数检查、交接包、任务及结果管理 | 用户在官网核对并提交、查看、继续生成；下载后明确导入 | 不使用 MJ 中转 API，不接管 Cookie，不后台自动提交，不假装轮询官网进度 |
| Banana API | 能力校验、提交、任务恢复、下载、成本与错误提示 | 用户选择供应商、真实模型 ID、凭证、计费方式 | 不把文字模型 `/chat/completions` 当图像接口；不共享文字服务 API Key |
| 提示词 | 完整沿用需求/分析/方向/迭代/最终产物，不只调用裸聊天接口 | 用户决定最终文本与素材用途 | 可独立复制、导出 Markdown/JSON/素材包，不强制生图 |

参考耀 AI 的模块分工：模型设置、角色化素材、任务关联置入信息、下载/缩略图分层。现有证据仅为可读模块与字符串，不宣称已复现其内部协议或全部界面。

整体验收：一个任务的每张结果，都能追溯输入版本、提交批次和素材；改提示词不会污染旧结果；重启不丢历史；PS 文档切换不会错放；没有 Banana 配置也能完整使用 MJ 与提示词导出。

## 二、版本修正与代码组织

1. 原 MJStudio、已安装 Prompt Wizard/Yao-AI、原 Prompt Wizard 源码均不覆盖；不迁移账户、Cookie、API Key、用户存档和生成图片。
2. `baselines/` 保存三个只读对照快照和 SHA-256 清单，默认不进入 Git；导入工具可复查、拒绝静默覆盖。
3. 安装版 Prompt Wizard **0.4.1** 为运行功能基线。`apps/prompt-wizard-compat/` 从该基线恢复可编辑的 Node/Electron 模块和原始前端构建产物。
4. 可编辑 React 源码 **0.3.4** 单独保留，包括原工作树尚未提交的改动。它不是 0.4.1 的完整前端源码；禁止用它的 Vite 构建覆盖新版 `dist`。0.4.1 的姿态库、窗口联动、图片备注等不能因整合丢失。
5. 工作台阶段 1 基线版本为 `0.1.0-dev.1`，阶段 2 为 `0.2.0-dev.1`，阶段 3 为 `0.3.0-dev.1`，阶段 4 开发版为 `0.4.0-dev.1`；输入契约版本 `0.1.0`，交换契约 `prompt-wizard-exchange/1`；兼容运行副本版本 `0.4.1-integration.1`。独立旧源码候选标记 `0.3.4-phase4.1`，仍不等同于 0.4.1 源码。各版本含义不同，不能简单一起改成“0.4.2”。
6. 本轮先恢复兼容运行代码、保留新版前端并建立构建保护；完整 React 源码收敛在阶段 4。若新版源码找不到，按功能逐项移植并测试，不能声称已经恢复。

目标目录：

```text
apps/workbench/             本轮先 CLI，下一阶段接 HTTP/UI
apps/prompt-wizard-compat/  0.4.1 兼容运行副本，前端 bundle 受保护
packages/core/             任务/版本/状态与参数编译
packages/storage/          原子持久化、素材、结果、导出
packages/adapters/         Prompt Wizard 交接；后续 Banana 与 PS
contracts/                 输入快照与后续 IPC/API 数据契约
scripts/                   基线导入、版本检查、隔离预览、迁移
tests/                     离线单元/集成/回归
.workbench/                新版独立数据区，不提交到 Git
```

## 三、分阶段实施

### 阶段 0.5：基线整合与版本纠偏（先做）

目标：能够确定“哪个文件来自哪个版本”，并保留现有可用功能。

操作：

1. 清点源码 Git 状态；从 ASAR 读取 0.4.1 模块、dist、姿态索引和 unpacked PS 文件；按白名单复制 0.3.4 源码和 MJStudio 代码，不复制用户数据。
2. 按文件归类相同、内容变化、安装版新增，输出可复查清单；源工作树的改动原样保留在独立快照。
3. 兼容副本采用 0.4.1 的服务/壳/构建产物；不盲目混合两版内部接口。禁止运行旧前端 build 覆盖新版 dist。
4. 预览使用独立数据与桥接目录、独立端口，不写现有 PromptWizard bridge.json、不自动安装插件、不读取原凭证。
5. 记录新旧版本关系、未恢复前端、尚未运行实测的功能；核对基线哈希。

验收：重复导入会拒绝覆盖；校验全部文件成功；隔离预览健康/静态页面可达；原源码 Git 状态不变。此阶段不是完整前端源码恢复。

### 阶段 1：任务内核与可恢复存储（计划后立即开始）

目标：先让每次操作对应可靠数据，避免界面做好后仍然结果串单。

操作：

1. JSON Schema + 运行时语义校验：重复资产 ID、文件/hash/图片尺寸、PS 引用/选区界限、确认 revision 一致性。
2. 持久化 `task → revisions → runs → results`。保存输入产生新 revision、清空确认；旧快照不可变。采用原子替换、独占写锁；崩溃不把坏 JSON 当空库；并发修改必须带期望版本。
3. MJ 编译器保留 `0 / false / null` 区别；开关仅 `--raw`，不出现 `--raw True`。正文已有参数和附加参数暂阻止自动编译，要求归一到字段或人工清单；不猜测冲突优先级。
4. 官网参数先以“提示词正文 + 可编译常规参数 + 网站核对单”交接。模型、速度、分辨率和参考图角色保留清单，未知版本绝不假装已校验。文件路径不放进提示词当 URL。
5. 人确认 prompt/settings/references 三项后才能产生 handoff；打开官网不改变状态；只有用户显式记录提交，才产生 runId。一个 revision 支持多次提交。
6. 结果导入必须显式指定 taskId/revision/runId，原始文件复制入素材区、算哈希；重复导入同文件同 run 幂等；不同 run 可引用同内容但关联独立。
7. Prompt Wizard 现有 Artifact JSON 可导入为草稿：保留 prompt/channel/params/checklist 的来源信息，参数建议放待核对清单，不静默选中某一条；不把缺失参考图当已附上。
8. 实现 CLI 以便离线验收；Banana submit 返回明确“未配置/未实现”，没有任何联网副作用。

验收：自动化测试覆盖版本失效、重启恢复、错误归属、0值、布尔、文件篡改、路径逃逸、写入冲突、重复导入、独立导出和 Banana 禁用。验收不依赖登录 MJ 或 PS。

### 阶段 2：MJ 官网协作界面与素材包

目标：在软件里高效准备，在官网亲自确认与提交，回来准确归档。

操作：

1. 延续 MJStudio 左输入/右任务结果布局与暗色工具界面，顶部明确 MJ 官网 / Banana API；不再展示 Relay token/base URL。
2. 输入区分需求、最终提示词、模型参数和角色化图片；每图选择 image/style/edit/base 等用途，分析缩略图标记“仅分析”。建立按模型版本的能力表和来源/更新时间。
3. 参数输入为空表示未指定；显示正文参数冲突、角色不支持和尺寸/体积问题。对 8.x edit 与旧 cref/omni 参数做版本化校验；正式上线前重新核对官方文档与实际账号能力。
4. 确认页完整展示将使用的文字、参数、图片、官网人工设置；任一改动使确认失效。按钮为“复制并准备官网”“打开官网”“我已在官网提交”，不设虚假“生成中百分比”。
5. 同源本地 HTTP API：限制 localhost Host/Origin、JSON 类型与体积；CSRF 防护、请求幂等键、结构化错误、按钮防重复、输入失败不清空。
6. 导出含 job.json、prompt.txt、官网清单、assets 的完整目录/zip；单纯提示词导出与素材包导出分别命名。
7. 拖入下载结果时先选任务/批次；不按文件名或时间自动匹配。显示全部结果缩略图、逐张/多张选择、预览、导出；缺失/破损图明确报错。

验收：一条人工 MJ 流程从输入到导出贯通；中文/长文本/窄窗/键盘可用；打开官网不等于提交；全部结果可选，而非仅 images[0]。正式官网提交由用户执行。

### 阶段 3：Prompt Wizard 结构化交换

目标：不再来回复制，提示词产物可以一键进入已选生成任务；不直接读取或覆盖 Prompt Wizard 内部数据库。

操作：

1. 建功能差异矩阵：精修、重构、姿态工作流、参考备注、窗口宽窄/托盘/伴随窗口、浏览器文本通道、存档和导出。先找对应新版源码；找不到则逐项迁移，不反编译 bundle 当长期源码。
2. 新前端构建至单独目录，不能覆盖受保护 0.4.1 dist；阶段 3 只通过显式契约交换，不提前切换 Electron 主入口。
3. 在最终产物增加“送到 MJ 任务”“送到 Banana 草稿”“仅导出”。通过明确任务契约交接，保留分析与提示词产物，而非只使用 `/api/chat`。
4. 图像按 assetId 去重；从生成任务继承角色/PS 上下文；如果只有缩略图，要求生产图替换/确认；返回任务后保留来源 workflowId。
5. MJ 参数建议拆成可选方案；用户选定一条再映射字段，无法识别的项必须核对。Banana 精修模板保留底图与参考图区别。
6. 存档仍由原应用管理，不直接读取、转换或覆盖内部数据库；结构化产物通过用户明确的导入/导出动作交换。

验收：提示词生成→编辑→送任务→确认→结果可追溯；仅导出仍可用；原应用、存档和现有 Prompt Wizard 功能不受影响。

### 阶段 4：统一 Electron 外壳与 Photoshop 安全闭环

目标：完成前端源码收敛和统一桌面外壳，保留 Photoshop 读取能力，并让结果能正确回到原文档和选区。

操作：

1. 在阶段 3 功能差异矩阵基础上逐项验证 0.4.1 功能；新前端构建到单独目录，全部回归通过后才解除保护并切换 Electron 主入口。
2. 抽象 PS adapter，先封装现有 COM，再接 UXP；所有 document/capture/place 操作带 requestId/sessionId，超时可恢复，状态请求不重叠。
3. 采集原始图、分析缩略图和生产快照分别存储；记录文档 ID、会话、画布尺寸、选区矩形及可用真实 mask，绝不以矩形冒充蒙版。
4. 建立坐标映射：分析图缩放、选区裁剪偏移、结果缩放和目标位置。用小尺寸人工 PSD 测试全图/非零偏移矩形/非矩形选区。
5. 回传前核对 session/document/画布尺寸，失效时让用户重新选目标；禁止退化为“当前激活文档”。置入新图层，支持 fit_canvas/fit_selection/new_document，不覆盖原层。
6. UXP 写操作走 executeAsModal；添加可撤销历史步骤；JSX 路径用 JSON 序列化，不拼接不转义字符串；临时目录 finally 清理。
7. PS 内多文档、关闭重开、重命名、尺寸改变、没有文档/选区、桥断线均有明确提示和取消路径。
8. 存档迁移先 dry-run 报告，再备份、转换、数量和哈希核对；旧存档不删。统一壳保留旧提示词功能与单独输出能力。

验收：0.4.1 功能矩阵全部通过才宣称版本收敛完成；PS-01/02 加上述边界用例需使用真实 PS 与用户指定测试文档完成，首次不在工作 PSD 上自动执行测试。

### 阶段 5：Banana API 适配

目标：在不影响 MJ 与提示词工作的前提下接入一个明确的图像服务。

前置决策：用户提供服务商/官方接口文档、模型 ID、鉴权方式、同步/异步协议、费用及限制；这些不是能从“banana”名称可靠推断的事实。缺失时只保留草稿/导出，不臆造接口。

操作：

1. Provider capabilities 描述 create/edit、多图/mask、尺寸/比例/格式/体积和计费；API Key 用 Electron safeStorage，不入任务包或日志。
2. 每次运行固定 provider 配置和模型快照；准备上传、请求 ID、幂等键、超时/取消与可追踪状态。明确“提交结果未知”不能直接重试付费请求。
3. 同步返回即解析；异步持久化 remoteJobId 再轮询，重启按该 ID 恢复，不重新提交。采用退避、总期限、限频、队列并发上限。
4. 下载只对匹配源站发送所需凭证，跨域/重定向移除鉴权；限制协议/主机/IP/体积/超时；校验真实图片类型，原子落盘。下载失败与生成失败分开，可仅重试下载。
5. 所有结果按共同 run/result 模型落库；支持逐图导出和 PS 回传；记录耗时/可用费用信息但不编造价格。

验收：离线 mock + 契约测试先通过；用户确认费用后做最小真实请求；超时、429、错误 JSON、未知提交、坏图和重启恢复测试通过。

### 阶段 6：发布、迁移与维护

目标：一个可回退的桌面版本，不以开发机特定路径才能运行。

操作：

1. 统一 Electron 应用 ID、端口占用处理、资源定位、日志脱敏、独立数据目录和升级号；确保只启动一个实例。
2. 删除运行路径中的硬编码用户目录，保留导入工具显式来源选项；依赖锁定、安全检查、离线测试和构建保护进入 release gate。
3. 旧 MJStudio 任务只读导入：未知状态标“待核对”，保留 raw legacy 元数据，不伪造 provider 或结果；迁移失败可重跑且不重复。
4. 打包 portable 先验证，再提供安装包；不自动覆盖旧版，不自动迁移凭证，不自动安装/更新 PS 插件；给出明确升级与回退步骤。
5. 回归矩阵覆盖 MJ 手工官网、Banana mock/真实受控、Prompt Wizard 各流程、PS、多图导出、崩溃恢复、无网络、文件夹中文/空格。

验收：干净目录运行、重启数据一致、可回退；发布说明区分已支持/实验性/未支持。保留旧应用直至用户确认新版稳定。

## 四、执行顺序与风险闸门

执行顺序固定为 0.5 → 1 → 2 → 3 → 4 → 5 → 6。阶段 3 可先完成源码寻找、差异比对和结构化交换，但不能以未验证的旧前端替代新版；Electron 主入口切换和 Photoshop 闭环属于阶段 4。

| 风险 | 防护与停点 |
|---|---|
| 0.4.1 React 源码缺失 | 保留原 bundle；完整整合前做功能恢复，不能仅改 version |
| MJ 网站版本/角色变化 | 版本化能力表、人工核对；未知能力不自动宣称有效 |
| PS 回错文档或破坏原层 | session/document 检查、新图层、可撤销；真实 PS 验收前不宣称闭环 |
| 付费重复提交 | 幂等键、remote ID、submission_unknown；需要用户确认后才再次提交 |
| 来源文件或结果丢失/串单 | 内容哈希、原始文件入库、revision/run 显式归属 |
| 用户数据污染 | 独立目录/端口/bridge，迁移先报告后执行，原应用不覆盖 |

当前阶段 0.5、1、2、3 已通过开发验收，阶段 4 正在执行。双向交换、PS 离线安全闭环与差异矩阵见 `docs/prompt-wizard-exchange.md`、`docs/photoshop-safety.md`、`docs/prompt-wizard-feature-matrix.md`。下一步继续收敛 0.4.1 功能并完成真实 PS 闸门，全部通过后才切换 Electron；真实 Banana API 留在阶段 5。
