## 2. 当前布局问题与最小调整

| 当前结构 | 使用上的影响 | 建议 |
|---|---|---|
| App 标题、页签、置顶、展开同一行；通道栏有多按钮和常驻说明 | 400px 宽度被低频操作和说明占据 | 窄版省产品标题；四个短页签；窗口动作归入菜单；通道栏只留当前通道与方案 |
| Intake 先展示整个 ArchivePanel | 一进入任务先看到管理功能 | 存档管理搬到独立页，任务只留保存/载入入口 |
| 原图、参考图、ResearchPanel、RefPlanPanel 排在需求前 | 多参考图时核心需求框排得很后 | 底图简卡和核心需求优先；资料折叠；参考图与分工合卡 |
| 参考图列表和分工列表分开 | 用户反复对照编号，长页面重复浏览 | 缩略图、编号、用途输入和删除放一张卡；缩略图可放大 |
| ResearchPanel 的前置必选字段在后面的字段表单 | 上方提示缺信息，但要向下寻找 | 前置字段移到资料面板内或提供就近定位；不复制两套状态 |
| Stepper 六阶段始终 flex-wrap | 窄版占多行 | 当前阶段 + 进度 + 展开历史；保留回退规则和下游作废提示 |
| 结果区全文、Markdown、JSON 并列；所有分段展开 | 复制当前步骤需要找按钮 | 当前步内容占主位；复制当前步为主操作；导出归入更多 |
| 窄版全局强制所有 grid 单列并隐藏横向溢出 | 缩略图小网格也被拆散，裁切可能被掩盖 | 各组件明确断点，长文件名省略、正文换行、flex 子项 min-width:0 |
| 资产页先展示缓存哈希 | 普通修改被技术信息干扰 | 先列规则与编辑器，哈希和来源放诊断折叠区 |
| 部分分工标签 10px、结果正文 12px | 长时间修图时阅读和点选吃力 | 正文建议 14px，辅助信息至少 12px；紧凑桌面控件仍有清晰命中区和键盘焦点 |

## 3. 推荐布局：同一状态、两种呈现

宽版约 1100px，达到约 960px 才用双栏。辅栏 280–340px，主栏吃剩余宽度；这不是全站强制双栏，设置和资产编辑按内容展开。

```text
向导  存档和预设  资产  设置                     窗口 ▾  收窄
通道 ▾  当前方案 ▾  [适用时显示思考等级]          连接状态
任务线路 / 当前阶段 / 输入摘要
┌──────────────────────┬───────────────┐
│ 主工作区              │ 图片与辅助信息 │
│ 接收：需求、约束、格式 │ 底图 / 参考图  │
│ 生成后：方向或结果     │ 分工 / 资料    │
│                       │ 或只读输入摘要 │
└──────────────────────┴───────────────┘
返回                         当前主操作       更多
```

窄版用于伴随 PS/耀 AI，保留单一滚动主区。输入和结果不能各有一套独立任务状态。

```text
向导  存档  资产  设置            窗口 ▾  展开
Gemini ▾     当前方案 ▾
原图精修 · 3/6 方向建议         步骤 ▾
──────────────────────────────────
当前阶段内容
输入阶段：底图简卡 → 需求 → 约束
          参考图与分工 → 格式摘要
结果阶段：第1步 / 第2步 / 第3步
          当前步正文
资料与高级项按需展开
──────────────────────────────────
返回                下一步 / 复制当前步
```

当最小高度和字体缩放让首屏放不下时，允许主区滚动，不压缩到无法阅读。固定操作栏须预留底部空间；错误显示在相关字段或主操作旁。
切页后返回原步骤与滚动位置；回退阶段的业务规则保持现状，不能因为打开资料或存档管理就作废结果。

## 4. 耀 AI 联动的可行性分层

| 级别 | 能力 | 结论与边界 |
|---|---|---|
| L1 窗口伴随 | 找到耀 AI 主窗口、靠边显示、跟随显隐、无激活恢复 | Windows 平台能力支持；本机目标句柄识别和叠放行为仍需原型实测 |
| L2 手动交接 | 复制当前提示词并切到耀 AI，用户粘贴提交 | 最容易交付；目标是少一次切窗，不宣称自动填入或提交 |
| L3 自动填入 | 通过正式外部接口填入提示词 | 未验证接口存在；Flutter/WebView 混合界面也不能预设稳定 DOM 或 UI 自动化定位 |
| L4 生成与回填 | 自动提交、进度、图片取回、PS 图层回填 | 当前证据不足；还需要鉴权、任务关联、重复提交防护及图层撤回协议，不列主线承诺 |

推荐 L1 + L2。独立浮窗、多任务编排不作为前提。

窗口事件建议按状态转换处理：

| 场景 | 助手动作 |
|---|---|
| 跟随关闭 | 普通独立窗口，使用手动窗口偏好 |
| 已绑定耀 AI 在前台 | 窄面板无激活显示；首次定位后保持停靠偏好 |
| 用户在助手输入 | 保持显示，不能因耀 AI 不再是前台立即隐藏 |
| 切到无关应用 | 跟随模式收起，后台任务继续；手动打开的宽工作台不突然隐藏 |
| 耀 AI 最小化或退出 | 隐藏伴随面板，托盘可找回；助手不退出 |
| 目标重启或多窗口 | 重新校验进程和句柄；身份不明确则暂停跟随并让用户选目标 |
| 手动拖动助手 | 暂停吸附，避免拉回；按钮可重新靠边 |
| 用户主动隐藏 | 记录手动隐藏，不因重复事件立刻弹出；通过手动显示或重新启用跟随恢复 |
| 目标显示器移除 | 夹回可用工作区，保留任务；不恢复到屏幕外 |

目标选择以可执行路径、PID 与窗口类型综合校验；事件处理使用去抖和去重，不持续调用 focus/置顶。对本助手的对话框和文件选择器也须保持可用，不能被跟随逻辑藏掉。
PS 内嵌的耀 AI 面板不一定有独立顶层窗口；该形态降级为跟随 Photoshop，不承诺识别某个 UXP 页签是否激活。

## 5. 技术边界与官方依据

- Electron `showInactive()` 支持显示而不激活窗口；`setVisibleOnAllWorkspaces()` 在 Windows 无效。`screen-saver` 属于可高于任务栏的层级，不能直接当作修复 PS 叠放的保证。[Electron BaseWindow](https://www.electronjs.org/docs/latest/api/base-window)
- Win32 `SetWinEventHook` 可监听窗口事件；调用线程需要消息循环。原型采用进程外监听，退出时解除监听并结束辅助进程。[Microsoft SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)
- 调整位置或叠放时要保留不激活语义；`SWP_NOACTIVATE` 是相应标志。前台切换有系统限制，L2 的失败应提示手动切换。[Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)

这里的官方能力证明方案具备实现基础，不证明本机耀 AI/PS 的所有场景已经通过。

## 6. 实施切分与验收

推荐顺序与工作量详见 `next-phase-plan.md`：先 P0 状态基础，再 P1/P2a/P5 布局，再主题与 P6a/P6b；语言与预设独立批次。

- UI：360/400/420/1100/1400px；100/125/150% DPI；空态、满参考图、长中文/英文、错误、运行中。检测实际元素越界与可点击性，不用隐藏滚动条冒充通过。
- 状态：切页、折叠、宽窄切换后草稿、参考图分工、未采用选择保留；载入旧存档不丢锁定项。
- 联动：耀 AI/PS/助手/其他应用轮流激活；PS 连续画笔操作；耀 AI 重启、最小化、多窗口、管理员权限差异、全屏、双屏混合 DPI、拔掉显示器、助手模态框。
- 交接：中文、英文、当前步、MJ 完整参数；复制失败不切窗；切窗失败不丢已复制内容；无程序时点击启动；绝不自动生成两次。
- 可退出：关闭跟随后无自动移动/显隐，辅助进程停止；隐藏时可从托盘找回。
