# v0.2.6

修掉「进入方向建议时无法确认 Gemini 已进入对话模式」的报错。

- 原因：Gemini 网页端现在只在“新对话”页渲染「对话 / 任务」开关，历史对话页整页没有这个控件。助手每次提交前都要确认模式，所以第一张图（新建对话）正常，第二张图之后（复用同一个 Gemini 对话）就报「未找到成对的对话/任务开关」。
- 修法：历史对话页没有开关时，改用输入框自身的类型提示做交叉验证 —— 对话是「问问 Gemini / 为 Gemini 输入提示」，任务是「描述任务」。读到的类型与所选方案一致才放行；读到相反类型时立刻报错并提示点「对话跑偏，重开」；读不到任何类型提示仍然报错，不猜。
- 模式仍然完全按所选方案走，不会自动换方案、也不会自动降级。
- 顺带把「开关在但选中样式读不出来」的判定也统一到同一套输入框证据，减少误报。

验证：在用户真实登录的 Gemini 对话页上直接执行新的判定逻辑，对话请求返回 `selected`（确认通过），任务请求返回 `unpaired`（立刻报错并给出下一步）；单元测试覆盖新增的历史对话页场景。
