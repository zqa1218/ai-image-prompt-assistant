## 二、总体设计

### 2.1 数据接入：索引进仓库，图片不进

```
构建脚本 scripts/build-pose-index.mjs
  catalog.csv + 文件系统校验
    → data/pose-index.json   （提交进 git，约 1 MB）
    → data/pose-catalog.meta.json（库版本、构建时间、计数）
```

索引单条：

```json
{ "id":"full_sexy_P001_front", "lib":"pose",
  "l1":"全身单人・性感系", "l2":"站姿", "l3":"正面",
  "name":"S形站姿・胯部侧顶", "group":"P001",
  "tags":[], "kw":"", "hair":"", "hairLength":"",
  "thumb":"thumbs/full_sexy_P001_front.jpg",
  "img":"img/full_sexy_P001_front.png",
  "adult": true }
```

- **图片不进 git、不进安装包**：库根目录作为「外部参考库」路径配置
- 服务器只读提供两类请求：
  - `GET /api/pose/index` → 索引（首次拉取后前端缓存）
  - `GET /api/pose/file?kind=thumb|img&id=...` → 带**路径白名单校验**（必须命中索引里的 id），只允许读库根下 `img/` `thumbs/`
- 库根解析顺序：本地配置（用户选过的目录）→ 默认 `W:\dsh\ref-libs` → 报"未找到参考库，请指定目录"

### 2.2 标签体系：并列维度，维度内 OR、维度间 AND

| 维度 | 取值来源 | 控件 |
|---|---|---|
| 库 | 姿势 / 服装 / 人像发型 | 单选 |
| 体系（一级） | 库里实际值 | 多选 chip |
| 动作（二级） | 库里实际值 | 多选 chip |
| 视角（三级） | 正面 / 侧面 / 斜侧 / 俯视 / 仰视 | 多选 chip |
| 服装标签 | 86 个 | 多选 chip（可搜索） |
| 发长 | 4 | 多选 chip |
| 发型 | 51 | 多选 chip（可搜索） |
| 自定义标签 | 用户补的 | 多选 chip（可增删） |

- 顶部一行**并列选择栏**（每维一个下拉/横向 chip 组），任意组合
- 结果区：瀑布/网格滚轮流，一次渲染 60 张，滚到底继续追加
- 选中卡显示：名称、体系·动作·视角、ID、尺寸、原图/缩略图切换

**姿势库补标签**（因原库 `标签` 为空）：以「体系 / 动作 / 视角 / 名称关键词」生成派生标签，并允许用户手动追加；自定义标签存 `data/pose-tags.local.json`（不进 git，随机器），避免污染上游索引。

### 2.3 新线路「人体姿势优化」

挂到 `WORKFLOWS` 第四条，5 个阶段：

| # | stage id | 标题 | mode | 内容 |
|---|---|---|---|---|
| 1 | intake | 接收 | form | 上传原图；想解决什么（僵硬/重心/手部/张力不足…）；可选参考图；下载目录（必填） |
| 2 | pose | 找姿势 | **hybrid** | 两个入口：① 标签检索 ② AI 推荐（见 2.4） |
| 3 | pick | 选定姿势 | choice | 展示选中的白膜图 + 「借用什么」（构图/重心/肢体朝向/张力），可多选 1–3 张 |
| 4 | compose | 生成提示词 | auto | 原图 + 所选姿势图 → 中文提示词（沿用 complete-cn 契约，追加「只借姿势不借人」约束） |
| 5 | export | 导出 | form | 下载所选白膜原图 + 提示词（.md/.txt），命名 `<名称>_<ID>` |

`pose` 阶段是**新交互**（不是现有表单）：左侧维度选择栏、右侧结果流；`mode: "hybrid"` 允许"手动选"与"AI 推荐后微调"混用。需要给 `stageSchema.mode` 增加 `gallery` 值（比 hybrid 更准确），或在组件层按 `stage.id === 'pose'` 特判——**建议新增 `gallery` 模式**，避免用 id 特判蔓延。

### 2.4 两种找法

**方式 1 · 标签检索（默认入口）**

```
选维度 → 实时过滤（前端，毫秒级）→ 结果流 → 点选 → 加入「已选」→ 去导出
```

约束：检索条件始终以索引里**真实存在的值**为选项，不允许输入不存在的分类（避免空结果）。

**方式 2 · AI 推荐**

```
上传原图 → 选通道（API / Gemini 网页）
  → 提示词：只允许从给定标签白名单里选（附全部合法值）
  → 返回 JSON：{ 诊断, 推荐标签组合, 每项理由, 备选组合 }
  → 白名单校验：非法值丢弃并提示「库里没有这个标签，最接近的是 X」
  → 用推荐组合预填检索条件 → 结果流（用户可改标签、可继续筛选）
  → 选中 → 导出
```

关键：**AI 永远只输出已存在的标签**，否则结果无法落地。白名单在服务端截断，不依赖模型自觉。

### 2.5 下载路径（先选路径再导出）

- 首次点「导出」或「找姿势」页顶部提示：`未设置下载目录` → 点「选择目录」调 `dialog.showOpenDialog({ properties:['openDirectory'] })`
- 目录存 localStorage（`promptwizard.downloadDir`），Electron 侧再校验可写
- 导出：复制**原图 png**（默认）或缩略图 jpg（可选），重命名 `<名称>_<ID>.<ext>`；同名已存在则加 `-2`
- 浏览器环境降级：逐张 `download` 触发浏览器下载

| 风险 | 应对 |
|---|---|
| 版权/再分发限制 | 只在本地读你的库，不打包、不转存、不上传；界面标注来源与「个人参考用途」 |

| AI 编造标签 | 服务端白名单截断 + 明确报错 |
| 与现有「资产」页混淆 | 资产页新增独立分区「姿势参考库」，与文本规则资产并列但不混排 |
