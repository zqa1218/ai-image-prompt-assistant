# v0.3.0

本次两个改动：**提示词不再夹带模型自己的建议**，以及**新增 ChatGPT 网页通道**。

## 1. 复制出去的提示词是纯净的

Gemini 有时会在提示词末尾补一句「建议使用 Gemini 的 Nano Banana 模型进行…」。这句话会被一起复制进绘图工具，属于脏数据。现在做了两道防线：

- 提示词层面：`prompt` 字段只放正文，结尾不得追加「建议使用…」「可以配合…」这类工具推荐、使用说明或寒暄，这类信息只写进 `channel` 字段（`src/lib/llm/task.ts`、`src/lib/llm/hairTask.ts`，网页请求包末尾也加了同样声明）。
- 应用层面：`src/lib/promptClean.ts` 在展示和复制前再兜一次，会剥掉末尾最多三行的工具推荐与收尾客套，也能剥掉和正文挤在同一行末尾的建议。

为避免误删正文，规则收得很紧：只从结尾往回剥、最多三行、剥完必须还剩足够正文；以 `【…】` 开头的是提示词分段标记，永远不动；带「禁止 / 不要 / 保持 / 保留 / 确认」这类指令词的结尾行按正文保留（例如「最后检查：确认没有换脸」不会被当成建议删掉）。

## 2. 新增 ChatGPT 网页通道

顶部渠道从两档变成三档：**Gemini 网页 / ChatGPT 网页 / API**。ChatGPT 通道和 Gemini 通道共用同一套 Skill 编译与提交流程，只是换成 `chatgpt.com`：

- 独立真实 Chrome / Edge 窗口承载会话，登录态在 `%APPDATA%\PromptWizard\chatgpt-browser`，与 Gemini 的浏览器配置、对话存档完全分开，互不影响；
- 按底图内容指纹绑定一个网页对话，未变化的附件不重复上传，全程不调用 OpenAI API；
- 「设置」页新增「ChatGPT 网页连接」卡片，可以看状态、一键打开登录窗口；
- 「对话跑偏，重开」在 ChatGPT 模式下同样可用。

顶部「网页方案」控制固定哪个模型：

- **沿用网页当前模型（默认）**：不动模型菜单，直接用你网页里已经选好的那个，最稳也最快；
- **Instant · 最快 / Thinking · 推理 / Pro · 最强 / 自动**：固定切到对应档位，菜单里找不到就报错，不偷偷换成别的模型。

切档位按子串匹配（Thinking / 思考、Instant / 快速 这类中英文差异都认），并让「文案最短的选项优先」，避免点到描述里也提到该词的其它档位。

已知限制：ChatGPT 网页的模型菜单文案与 DOM 会随官方改版变化，固定档位方案依赖当前选择器；默认的「沿用网页当前模型」不依赖菜单，改版也不会失效。

## 其他

- 服务端网页接口改为按渠道分派：`/api/web/status|open|reset?channel=gemini-web|chatgpt-web`，旧的 `/api/gemini/*` 保持可用。
- 测试基线：`npx vitest run` 180 项（176 通过 / 4 跳过），`npx tsc --noEmit` 通过。
