# v0.2.8

修掉「下一张图之后／换一条线之后／重开之后，修图需求打不了字」。

- 原因：这三个操作原本都用原生 `window.confirm()` 确认。Windows 上 Electron 的原生模态框是把属主窗口置为「禁用」状态的模态循环，关掉对话框后偶尔不会恢复，之后鼠标点击就不再送进页面窗口，键盘事件也进不来。用户看到的现象就是「修图需求点不动、输不进字」——输入框本身其实是好的（`disabled` / `readOnly` 都是 false，状态里需求也还在）。
- 三个操作现在都走应用内确认框：不阻塞渲染进程，Esc 取消、确定按钮可键盘操作，不再有原生模态循环。
- 兜底：渲染进程启动时就把原生 `alert` / `confirm` / `prompt` 覆盖掉，将来任何漏网调用都不会再弹原生框；主进程在窗口重新获得焦点时把键盘焦点交回页面。并加了一条回归测试，源码里一旦再出现原生 `confirm(` 就会失败。
- 「下一张图」（含沿用参考图）和「对话跑偏重开」之后，会自动把光标放回「修图需求」输入框，接着改就行。
- 顺带修掉「修图需求」这类字段的可点击范围：原来用 `<label>` 把控件包住，点击标签文字依赖浏览器默认转发；现在改成 `htmlFor` + `id` 显式绑定，标签文字、整行都能稳稳点进输入框。

验证：单元测试从 152 条增加到 159 条（新增应用内确认框的确定/取消/并发替换、原生对话框拦截、需求输入框定位契约）；真机复测「下一张图 → 修图需求可直接输入」。
