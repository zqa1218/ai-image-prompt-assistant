# v0.2.7

修掉「上传完参考图后 Gemini 开始创建您的图片，而不是继续分析」。

- 原因：点一次「开始分析」其实发两次请求。第一次只带底图做分析；紧接着第二次把参考图传上去做「拆解可迁移元素」。Gemini 4 看到带图消息 + 「迁移到另一张照片」这类字样，把它当成改图指令，直接开始生成图片；模型正文一直是空的，助手只能干等到 180 秒超时。
- 提示词层：每条网页请求的开头和结尾都加「纯文字任务 · 禁止生成图片」，并明确说明「修图 / 置入 / 迁移」这些字样描述的是要写进**文字提示词**里的内容，不是让它动手改图；图像编辑由另一个工具执行。每个阶段的「输出要求」里也加了同一条约束（网页端与 API 端都生效）。
- 运行时层：检测到网页正在生成图片（有停止按钮且出现「正在创建您的图片」）而正文一直是空的，6 秒即停：点网页的停止按钮中止这次生成，并报出「Gemini 把这次请求误判成生成图片」，不再白等三分钟。
- 参考图拆解失败以前是静默的（只在内部吞掉）。现在会在界面上说明原因，用户能知道参考图没被读到。
- 上传参考图时的「Gemini 的上传菜单中找不到“上传文件”」是真的找错了原因：Gemini 窗口被别的窗口挡住（或最小化）时，网页处于 `document.visibilityState === 'hidden'`，Chrome 会**直接丢弃合成的鼠标事件**，于是点“+”什么都不会发生，菜单自然不出现。现在会话建立时就打开焦点模拟，并且改用元素自身的 `click()` 打开上传菜单、直接把文件塞给网页的隐藏 input；坐标点击只作为重试兜底。用户不必再先把 Gemini 窗口切到最前面。
- Gemini 在引用附件的段落下会挂「JPG +2」这类来源角标，它们会被当成正文读进提示词里。现在读取回复时会先把这些角标排除。
- Escape 键以前被错发成回车（`keyEventParams` 写死了 Enter），关菜单的按键有风险；现在按真实按键分发。

验证：单元测试覆盖纯文字约束的位置（必须在正文之前）、各阶段输出要求、「网页开始生成图片就停止并报错」、「坐标点击全部失效时仍能打开上传菜单」以及「元素 click() 无效时退回坐标点击」；真机复测把底图 + 2 张参考图重新提交，确认能上传并得到文字回复。
