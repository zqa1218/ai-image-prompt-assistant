# 待研究：收窄不是「真收窗」，以及模块拆分方向

## 现象（0.4.3 实测）

点「收窄 / 展开」只改变了**内容列宽度**（`html[data-shell]` 驱动 CSS），
**宿主窗口本身没有跟着变窄**。也就是说「伴随面板」目前只是个样子，不能长期停在 400px 常驻。

## 根因（已定位，未修）

IPC 桥没生效，`window.pwShell` 在渲染进程里是 `undefined`，所以 `syncWindow()` 静默跳过（代码里写了可选链，降级成"只改布局"）。

原因大概率是 **`sandbox: true` 不支持 ESM preload**：

```js
// electron/main.mjs
webPreferences: { contextIsolation: true, sandbox: true, preload: path.join(here, 'preload.mjs') }
```

Electron 里 preload 在 sandbox 模式下必须是 CommonJS，`.mjs` 会被静默忽略（不报错，只是 `window.pwShell` 不存在）。

**可用修法（择一）**：

1. preload 改 `.cjs` + `require('electron')`，`sandbox` 保持 `true`（推荐，不牺牲沙箱）
2. 或 `sandbox: false` 保留 `.mjs`（安全性下降，不推荐）

验证方式：`window.pwShell` 是否为对象；点收窄后窗口宽高是否变化。

## 用户要的最终形态：模块拆分

不是「整体窗口缩窄」，而是**把功能拆成可独立开合的面板**，参考：

- **耀 AI**：主窗口 + 独立浮层/面板，各自有生命周期
- **夏三七的修图轮椅**：常驻的窄浮层（平台工作流 / 生成 / 剪影预设 / 设置 / 外挂能力），
  一行一个模块，点进去展开，浮在 Photoshop 上

对应到本项目的拆分建议：

| 模块 | 内容 | 形态 |
|---|---|---|
| 任务面板 | 三条线选择、当前阶段、进度 | 常驻窄条 |
| 输入面板 | 原图/参考图/需求字段 | 可折叠 |
| 结果面板 | 方向、提示词分段、复制 | 可折叠，主要工作区 |
| 资料面板 | 资料收集 / 人设卡 / 参考图分工 | 按需展开 |
| 设置面板 | 通道、API 状态灯 | 独立窗口或抽屉 |

拆分的先决条件是 **状态统一（阶段 3）**：每个面板要能独立挂载/卸载而不丢任务状态，
否则拆完就变成"每开一个面板丢一次选择"。所以顺序是：阶段 3 状态统一 → 再做面板拆分。

## 修复记录（0.4.5–0.4.7）

**preload 改 CommonJS 后桥通了**，实测：

```
typeof window.pwShell = object
初始   1101×821
收窄    401×822   ← 窗口真的变窄
展开   1102×822
置顶返回值 true
```

**仍有 1px 级漂移**：显示器工作区 1707×1019（非 100% 缩放），
Electron 在 DIP ↔ 物理像素之间往返取整，宽或高每切换一次可能 +1。
已尝试两种写法（`setSize`、以首次 `getBounds` 为基准的 `setBounds`），都能缩小漂移幅度但没消除。

判断：**属于 DPI 取整，不影响功能，暂不再投入**。
若将来要做「记忆窗口位置与尺寸」，建议按物理像素存 + 恢复时用 `setContentBounds`，并接受 ±1。
