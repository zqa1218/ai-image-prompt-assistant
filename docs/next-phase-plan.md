> 汇总：三项结构改造 + 输入区重组 + 视觉主题 + 既有待办。
> 依据：`docs/pending-shell-modules.md`、`docs/pending-intake-restructure.md`、`docs/dual-view-execution-plan.md`。
> 状态：**方案待选择，尚未实施**。2026-10-27 已按现有源码和本机耀 AI 安装情况补充评估。
> 推荐顺序：P0 → P1 → P2a → P5 → P3 → P6a/P6b → P4 → P2b；P6c 独立研究。
> 详细布局、联动边界和验收见 [界面布局与耀 AI 联动评估](ui-yao-integration-review.md)。以下新增建议不代表用户已经批准实现。

## 一、已确认的决策

| 议题 | 决定 |
|---|---|
| 视觉主题 | **暗色底 + 淡粉强调**，毛玻璃只用于最外层 |
| 导航 | **两级**：一级页签 + 二级工具条 |
| 预设库 | **最小版**：存 / 搜 / 套用 |

| 额外效果 | 放**要求区** |

| 保持不变 | 固化为快捷标签，点击写入约束框 |
| MJ 线 | 语言锁定英文、只读 |

## 二、阶段划分

### P0 · 状态与存档基础（新增，0.5–1 天，不含测试环境排障）

- 修复 `server/archives.mjs` 的图片归一化未保留参考图 `note`：已有独立临时目录复现，保存后逐张分工丢失。
- 明确当前存档是「输入配置 + 图片」，不是完整任务快照；重启自动恢复目前仅包含线路和需求。
- 检查页签切换/模块折叠前未采用的选择和草稿：`ResearchPanel.picked`、`AssetsPage.draft` 等仍是组件局部状态。任务编辑状态迁入稳定存储，临时 UI 状态按需保留。
- 外壳启动后同步已保存的宽窄/置顶偏好到主进程，读取真实状态再更新按钮；当前 `layoutStore` 只在用户操作时调用 IPC。
- 验收：参考图分工存读一致；切页和折叠不丢草稿；启动后的实际窗口与显示状态一致。先解决当前 Vitest 启动停滞，再建立回归基线；类型检查通过不替代测试通过。

### P1 · 导航与信息架构（0.5–1 天）

**目标**：顶部不再挤，给「存档和预设」腾出一级位置。

1. 一级页签改为：`向导 | 存档和预设 | 资产 | 设置`
2. 二级工具条（页签下方一条细栏）：**通道下拉**、网页方案、思考等级
3. 通道三按钮 → 下拉：
   - 选项 = `Gemini 网页`、`ChatGPT 网页`、`API`
   - 首版 API 项只切到当前 API 配置。现有供应商预设仅含地址和模型，不是已保存账号；跨服务切换会触发必须提供新 Key 的保护
   - 多 API 账号另排增强项：每份配置独立加密保存 Key，原子切换地址/模型/凭据后才允许选择
   - 当前通道用文字图标表示，不再用三个并列按钮
4. 窄模式下二级工具条可折叠为一行（只留通道 + 当前方案）
5. 新增布局建议：窄版导航用 `向导 | 存档 | 资产 | 设置` 短标签；置顶与窗口联动放「窗口」菜单，展开入口保留；隐藏重复产品标题。
6. 工具条只在向导页显示；网页方案仅在网页通道出现，思考等级按通道能力显示。说明文字移至帮助入口，失败原因就近显示。
7. 存档列表移出接收阶段首屏，向导只保留「保存输入 / 载入」快捷入口。

**验收**：窄版（400px）顶部不换行、不横向滚动；三个通道都能通过下拉切换并生效。

### P2a · 输入区三区重组（1.5–2 天，不含语言规则改造）

**目标**：把 18 个字段收成三块，默认填写时间显著下降。

- **约束区**
  - `保持不变` 变为快捷标签，点击把「保持不变：人物身份与脸」追加进约束框
  - 约束框（多行，原有 `constraints`）
- **要求区**
  - `修图需求`（多行，语言随意）
  - 修改区域 / 修改内容 / 采用的模式
  - 参考图可取部分（与逐张分工合并展示）
  - 效果描述预设 + 额外效果（手写）
- **格式区**
  - 模式：置入物品（纯正语言）/ 参考图（`参考图1、2…` 标记）
  - 语言：中文 / 英文（MJ 锁定英文）
  - 输出模式与尺寸

实现要点：

1. 字段加 `group: 'constraint' | 'requirement' | 'format'`，**只影响界面**，编译仍平铺
2. 「任务类型」→ 5 个快捷模板（质感升级 / 换背景 / 置入物体 / 局部修改 / 自定义）+「展开更多」折叠区
3. 折叠只控制显示，不改变字段值或请求编译。不要复用 `showWhen` 表达「收起」，因为 `visibleFields` 也用于请求编译；未指定位置保持自动判断，不静默强制中景。
4. 旧 `preserve` 字段兼容迁移到约束框，去重且可再次载入；快捷标签重复点击不重复插入。
5. 默认阅读顺序建议：底图简卡 → 修图需求与任务模板 → 约束 → 参考图及逐张分工 → 格式摘要。资料与人设按需展开；它们的必填前置项放在同一面板内。
6. 宽版接收阶段双栏：主栏需求/约束/格式，辅栏底图/参考图/资料；窄版单列。参考图缩略图与分工放在同一卡片，避免图片和分工两份长列表。

**验收**：同一输入在折叠前后生成相同请求字段；旧存档锁定项不丢失；各线路按自己的输出结构验收，完整连续正文不能强制按 `【标题】` 分段。无参考图、12 张参考图、长需求与长文件名均可操作。

### P2b · 语言与参考图引用规则（独立批次，1.5–3 天）

- 检查任务说明、输出契约、固定资产、清洗与导出中的语言约束，不只替换一处「中文」。
- 定义「工作流 × 步骤 × 语言 × 引用模式」矩阵；保留已确认的中文标题、中文 channel/checklist、MJ 英文锁定。
- 分步线第 2 步当前固定点名引用参考图；全局格式设置与该规则的优先级必须明确，首版建议按步骤固定并展示，避免提供无效开关。
- 只在要求消隐的正文检查参考图来源，不全局禁止 `reference`；不得通过删掉整句而丢失物体特征。测试同时检查引用合法性和描述保留。
- 文档曾引用的 `Du()` 清洗函数在当前源码未找到；按缺失能力设计，不作为现成基础估时。

### P3 · 主题视觉（1–1.5 天）

**目标**：暗粉毛玻璃，替换现在的纯色深灰。

1. 令牌：底色沿用 `ink-900/850`，强调色改**淡粉**（主 `#f0a6c0` 一类）、次强调淡青
2. 毛玻璃只用于最外层外壳；卡片、输入框和正文保持不透明，统一与已确认决策一致
3. 状态色与强调色分离（成功/警告不跟着变粉）
4. 全站替换一遍，处理与现有 `neutral-*` 的残留冲突（上次踩过白字压白底）

**验收**：对比度 ≥ 4.5:1；暗粉不用于错误提示；窄宽两模式都正常。

### P4 · 存档与预设（1.5–2 天）

1. 一级页「存档和预设」：两段式（存档列表 / 预设列表）
2. 输入存档沿用现有功能并修复分工丢失；完整任务恢复另行设计，不能在入口搬家时宣称已经具备
3. 预设最小版：
   - 存：当前三步产物 → 另存为预设（名称、分类、适用步骤）
   - 搜：按名称与分类
   - 套用：预览 → 选目标步骤 → 确认写入，可撤回
4. 预设与存档解耦：预设记录来源任务 ID，但存档删了预设仍可用
5. 首版从当前结果保存预设；历史输入存档无生成结果，不能直接抽取提示词。套用绑定任务 ID 与目标版本；用户后续编辑后，撤回不得覆盖新编辑。

**验收**：存→搜→套用→撤回全通；删除来源存档后预设仍可用。

### P5 · 宽窄工作区组织（依赖 P0、P1、P2a，1–2 天）

首版采用同窗面板，独立浮窗不在这一批实现：

- 宽版：共享主工作区 + 280–340px 辅栏，约 960px 以下切单列。接收阶段主栏填写需求，生成后主栏展示结果，辅栏显示只读任务摘要。
- 窄版：360–420px；固定简洁导航与当前阶段摘要（如 3/6），历史阶段按需展开；底部保留一个主操作及必要的返回/更多。
- 分步结果：选择第 1/2/3 步并复制当前步，默认看当前步；全文预览与导出放更多，保留原有复制全文能力。
- 底部操作栏给正文留足空间，键盘焦点不被遮住；只有主内容区滚动，避免多层滚动。
- 用组件级断点处理布局，逐步移除全局 `[class*='grid-cols-'] !important`；不能靠 `overflow-x:hidden` 掩盖被裁切的控件。
- 布局折叠状态与任务字段分离，切宽窄/切页/展开收起不改变模型输入。

**验收**：360/400/420/1100/1400px；100/125/150% DPI；空态、长内容、忙碌、错误、12 张参考图；切页与宽窄往返 10 次不丢选择。截图检查并测量实际溢出，不只检查是否出现滚动条。

### P6 · 耀 AI 与 Photoshop 伴随联动（正式列入计划，分层交付）

本机已发现耀 AI 桌面 EXE 与 YaoAI-Link 2.6.2；检查时耀 AI/PS 未运行，以下是可行性评估，不是已完成联调。

#### P6a · 窗口联动原型与首版（先 0.5–1 天验证，再 1.5–3 天实现）

- 绑定用户选择的耀 AI 主窗口；优先按可执行路径和进程身份识别，窗口标题仅辅助。多窗口不能随便取第一个。
- 默认关闭；设置中提供「关闭 / 跟随耀 AI / 跟随 Photoshop」，独立「始终置顶」与跟随模式互斥，避免争抢。
- 目标在前台时无激活显示助手；切到助手编辑时保留；切到无关应用时收起。目标退出/最小化时隐藏伴随面板，不取消任务、不退出助手。
- 托盘或用户配置快捷键可手动找回；用户手动隐藏后不立即自动弹回，显示/隐藏原因分别记录。
- 首版只移动和显示本助手，靠目标左/右侧吸附；空间不足停靠工作区边缘。手动拖离即暂停吸附；跨屏用目标显示器坐标和 DPI 转换，保存 DIP bounds、显示器标识及停靠偏好，恢复时夹到有效工作区，接受 ±1px。
- 技术原型优先验证 Win32 窗口事件监听（进程外、需消息循环）与 Electron `showInactive`；单个可退出的辅助进程即可，不预先引入常驻服务。仅事件变化时处理，禁止循环抢前台。
- 删除旧文档建议中的 Windows `setVisibleOnAllWorkspaces` 修法：官方文档明确该 API 在 Windows 无效。`screen-saver` 会影响任务栏上方层级，不作为默认值或必然修复方案。
- 失败降级：识别不到窗口、权限不同或辅助进程失败时，回到手动独立窗口，显示明确原因，不要求用户默认管理员运行。

**原型通过条件**：真实耀 AI 主窗口可区分；PS 画笔操作不被抢焦点；目标/助手/无关应用三种前台切换逻辑成立。若不通过，只交付手动置顶与位置记忆，保留失败记录并重估自动跟随。

#### P6b · 提示词交接（0.5–1 天，依赖 P5 与窗口定位能力）

- 结果区新增「复制并切到耀 AI」，明确是剪贴板交接，用户自行粘贴与提交。
- 分步线默认只交接当前步；MJ 交接完整可用的一行（含参数），不混入说明或 QA 清单。
- 先确认复制成功，再尝试切换目标窗口；切换被系统拒绝时保留复制成功提示，允许手动切换，不重复提交。
- 耀 AI 未启动时显示「复制并打开耀 AI」，仅由用户点击后启动已验证路径；不自动启动、不模拟 Ctrl+V/回车。

#### P6c · 深度联动探索（独立 1–2 天调查，不承诺功能交付）

- YaoAI-Link 的现有桥是桌面调用 PS 的通道；源码所见接收白名单为 `ps.* / app.ping`，不能据此认定有第三方提示词写入/生成 API；IPC 文件也标注预留。
- 先取得并验证对外接口、协议版本和外部客户端身份，再讨论提示词写入、结果取回、PS 图层回填；不冒充 Link、不复用其桥接凭据、不修改耀 AI 安装文件。
- 没有受支持接口时维持 P6b。自动提交/出图/回填仍不进入 0.5.x 主线；从文字推断任务类型也留后续。

## 三、顺序理由

先处理状态与存档，再改导航和输入；当前通道栏已经在外壳中，P1 是压缩与重排，不是从输入区迁出。
同窗宽窄布局在上色前稳定，之后交付主题；窗口伴随在任务状态可靠后实施。预设库与双语输出按用户优先级独立交付。
建议先选择「同窗双布局 + P6a/P6b 轻量联动」。P6a 的原型结果是自动跟随的交付门槛，P6c 不是主线依赖。工期是单人有效工作日粗估，截图/DPI/真实应用联调和问题修复应保留余量，不再以原 P1–P4 的 4.5–6.5 天代表完整版本。

## 四、风险

| 风险 | 应对 |
|---|---|
| 三区重组动到编译逻辑 | 分区只影响界面；编译保持平铺，改完用「同需求新旧对比」验收 |
| 语言/引用模式冲突 | 按工作流和步骤验收；允许引用的步骤不得统一禁用 reference |
| 折叠改变语义或丢草稿 | UI 折叠不修改编译字段；显式区分自动值与用户选择，跨挂载保留编辑状态 |
| 主题改造再次出现类名冲突 | 复用上次的冲突清理脚本，改完必截图核对 |
| 联动窗口抢焦点、移出屏幕或找错目标 | 原型先验证识别；不激活显示；工作区夹取；随时手动退出跟随 |
| 耀 AI 私有桥并非开放接口 | 窗口/剪贴板先交付；正式接口验证通过才另立深度联动任务 |

## 五、明确不做

- 耀 AI 自动提交/取回/PS 图层联动
- 多任务并发、云同步、多用户
- 自动导入他人商业预设
