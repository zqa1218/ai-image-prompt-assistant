# 阶段 0：MJ 官网协作 / Banana API

决策日期：2026-11-12。状态：流程与任务交接草案已落地；运行实现从阶段 1 开始。

## 1. 已确定的范围

| 项目 | 决策 |
|---|---|
| MJ 生成通道 | 用户自己的官网操作流程；本地不调用第三方 MJ 生图 API |
| MJ 提交责任 | 用户确认提示词、参数、参考图后，在官网亲自提交 |
| MJ 进度与生成结果查看 | 以官网为准，本地不模拟实时进度或推断已生成 |
| MJ 结果回收 | 下载后拖入/选择文件，人工确认所属本地任务；收件目录监听可后加 |
| Banana 生成通道 | API，待选定服务商和模型；不假定其兼容某个文本 API |
| 提示词来源 | 用户直接输入，或 Prompt Wizard 的完整工作流产物 |
| 独立导出 | 两种模式始终支持复制、Markdown/TXT、JSON 与素材包 |
| Photoshop | 共享双向桥接，保留源文档、选区及回传上下文 |
| 界面参考 | 借鉴耀 AI 的模型参数组织和素材/任务分离；本地静态证据不是其完整 UI 或官网接入协议 |

MJ 官网协作的确认是产品中的必要步骤，来自用户本次要求，不是开发阶段额外的授权关卡。打开官网、复制成功、用户点击本地确认均不代表官网已经接收任务。

## 2. MJ 从输入到回传

1. **建立草稿。** 选择 MJ 模式；输入需求或完整提示词；从 PS、文件、剪贴板添加素材。
2. **整理参考图。** 每张图指定用途，标明是否仅供提示词分析。允许锁定、移除、排序和复用。
3. **确定提示词。** 保留用户需求、生成过程与最终正文；正文与参数分开存储。
4. **确定设置。** 用户选择模型版本及参数，检查官网专属设置；参数预设只能提供初值。
5. **确认本次方案。** 同一页列出最终文字、参数和全部提交参考图；用户确认后生成不可变修订快照。
6. **前往 MJ 官网。** 提供“复制提交文本”“打开参考图文件夹”“打开 MJ 官网”。可组合为便捷动作，但分别报告复制/导出/打开结果。用户自己上传参考图、指定用途、检查设置并提交。
7. **在官网查看。** 本地提供“我已在官网提交”和“打开官网查看”；可记录用户粘贴的官网 Job ID/链接。没有 Job ID 时只打开官网创作页。
8. **导入结果。** 用户下载后选择本地任务及修订，再导入一个或多个文件。导入预览核对图片、任务、修订和可选 Job ID，确认后建立关联。
9. **选择与输出。** 每张结果可预览、比较、标记、导出或回传 PS；重跑/变体等在官网执行，结果按新运行记录关联。

修改已经确认的文字、图片、图片用途、顺序、模型或参数，必须增加 `revision` 并清除当前确认；旧快照留存。一次修订可以对应多次官网运行，每次使用独立 `runId`，不能覆盖前一批结果。

首版不依靠“最近下载的文件”“最新任务”或文件时间推断归属。无法确认归属的图片留在未关联收件区。没有记录官网提交事件，也允许人工将结果关联到一个已确认修订，事件来源标记为 `manual_import`。

## 3. 参数与参考图规则

### 3.1 参数面板

| 分组 | 本地设置 | 向官网交接方式 |
|---|---|---|
| 模型 | 版本、创作/编辑操作 | 必选明确版本；从官网当前可见选项确认，不假装发现了账号可用模型 |
| 画面 | 比例、输出分辨率 | 编译器只输出已核实支持的语法，其余列为官网设置清单 |
| 风格 | Raw、Stylize、Variety/Chaos、Weird | 类型与版本能力校验；0 是有效值；布尔开关不能拼成 `--raw True` |
| 随机性 | Seed | 留空与 0 区分；记录最终数值，不承诺跨版本或同 Seed 完全复现 |
| 运行 | Fast/Relax/Turbo | 账号是否支持由用户在官网核对 |
| 官网专属 | 个性化、Moodboard、隐私等 | 按版本/账号验证；不能编码进文字的设置进入人工核对清单 |
| 高级 | 额外参数文本 | 解析重复/冲突参数；未知项明确提示，由用户解决后确认 |

任务设置是事实来源，编译后的可复制文字是派生产物。用户输入的提示词如果已包含参数，先拆出并提示冲突，不再追加第二套互相冲突的参数。

`null` 表示本地尚未指定/未记录，不表示官网默认值。确认前，用户必须明确所需设置，或明确选择保留官网设置；后者写入人工清单。程序不能宣称官网当前值与本地一致。

模型能力表需包含版本、操作、支持参数、参考图类型、限制、证据链接、核对日期。未验证的组合不得静默映射到另一种用途。日期过期提示用于复核，不擅自改变已确认任务。

### 3.2 图片角色

| 角色 | 含义 |
|---|---|
| `base` | 编辑底图；对 Banana 是编辑基准，MJ 中需要按所选版本转换为明确的官网操作 |
| `image_prompt` | 画面内容、构图等参考 |
| `style_reference` | 风格参考 |
| `edit_reference` | 所选 MJ 版本的 Edit Model 参考 |
| `character_reference` | 版本相关的主体一致性参考；不固定编译成 `--cref` 或 Omni |
| `mask` | 编辑/回填蒙版；不是普通参考图，除非接口明确支持，否则不作为普通图片发送 |

`analysisOnly=true` 的素材只给提示词分析使用，不能默认上传给生图服务。官网角色与模型限制以当前官方文档为准；本地通用素材数量不是官网允许数量。

官网目前说明单张上传上限为 10 MB；本地原图可以更大，但要另存符合限制的提交副本。当前 Edit Model 文档说明最多四张编辑参考，并有版本兼容要求。这些限制记录在能力表中，不施加为所有模式的统一常数。[1][2]

本地路径、`/refs/...`、data URL 均不能假装成 MJ 已上传的图片 URL。官网协作包包含独立图片文件、排序和用途清单，由用户上传/选择。

原始素材、分析缩略图和提交副本分别保存，使用资产 ID/内容哈希关联。修改文件内容需要新资产版本并重新确认。第一张编辑参考的顺序有实际含义，不能按文件名字母自动重排。

## 4. 本地状态与结果关联

任务包描述一个输入修订；运行状态、网络请求、图片下载与 PS 操作记录保存在独立运行记录中。

| MJ 本地状态 | 进入依据 | 界面解释 |
|---|---|---|
| `draft` | 创建或编辑 | 草稿 |
| `ready_for_web` | 三项确认完成且语义校验通过 | 已确认，待去官网 |
| `submitted_by_user` | 用户声明已经提交，记录时间/可选 Job ID | 本人已提交，请到官网查看；不是远端状态确认 |
| `results_imported` | 至少一张有效图片被确认关联 | 结果已导入；不承诺该批全部完成 |
| `archived` | 用户收起任务 | 已归档；不表示已取消官网任务 |

“打开官网”是事件，不触发 `submitted_by_user`。MJ 不使用假的 `running/progress`，不轮询官网内部接口。不支持本地“取消官网生成”按钮。

每次官网运行记录 `runId / taskId / revision / reportedSubmittedAt / webJobId? / webJobUrl? / evidenceSource`。官网链接只接受核实的 Midjourney 网页地址，不拼造未知深链。

每张结果记录 `resultId / runId / assetId / importedAt / sourceJobId? / selected`。`sourceJobId` 与当前运行不同或无法确认时，要求用户重新选择归属。预览拼图、裁切图与独立原图分开标识，不把本地裁切称为官方高清输出。

## 5. Banana API 预留

首版保留 Banana 配置入口与同一套任务草稿/导出能力。在服务商、模型 ID、鉴权和图像请求/响应结构尚未确定时，禁用真实生成并说明缺失项。

计划运行状态：`queued → submitting → running（若为异步接口）→ downloading → ready`。同步返回图片的接口可从 `submitting` 进入 `downloading`。另外保留 `submission_unknown / download_failed / failed`。

提交超时不等于服务商未接收；先按请求 ID/服务商机制查证，没有机制时交由用户判断重提，不能自动重复扣费。下载失败只重试下载。提供方不支持取消时，只能停止本地等待，不能承诺远端取消。

文本模型与图像模型配置分离：Prompt Wizard 现有的 `chat/completions` 接口不能直接当作 Banana 图像生成接口。任务包只存 `providerId`，API Key 留在本机凭证存储，不随 JSON/ZIP 导出。

## 6. Prompt Wizard 和 Photoshop

### 6.1 提示词交接

复用 Prompt Wizard 的 `Artifact` 和工作流上下文：将最终正文、参数候选、素材、需求与 workflow ID 转换成任务草稿。候选参数必须经过 MJ 参数面板确认，不直接执行。阶段 0 的 Schema 不取代现有 Artifact，而是定义它向生图工作台的输出边界。

MJ 默认对接 `recompose`，Banana 默认对接 `refine`；允许直接手写，不强制通过向导。任务模式切换时清除确认，从创作意图重新编译，不把 MJ 参数混入 Banana 编辑指令。

统一输出动作：复制提示词、导出 Markdown/TXT、导出 JSON 和参考图包。源工程已存在 Markdown/JSON 导出，可扩展为带素材和版本信息的任务包。

### 6.2 PS 上下文

UXP 为后续主通道，COM 暂作兼容。记录 PS 会话标识、文档 ID/名称、画布尺寸、抓取资产 ID、抓取范围、选区边界和蒙版资产。0.1.0 的抓图范围限整画布或选区外接框，按范围与抓取资产尺寸计算缩放/平移；将来加入扩边、旋转或额外裁切时升级契约，显式记录完整变换。文档 ID 不能当作跨 PS 重启不变的永久标识。

默认以新图层/智能对象回传，允许适配原选区、适配画布和新建文档。回填前校验会话、目标文档和画布；切换文档不能改变任务原始目标。原文档关闭、重开或尺寸变化后先重新绑定。非矩形选区需要真实蒙版，外接矩形不能替代蒙版。

导出包中的 PS 信息用于追溯，导入另一机器后不可直接操作同 ID 文档；须重新建立会话绑定。PS 写操作串行执行，记录单次可撤销操作；失败不能显示成功。

## 7. 交接契约及后续接口边界

文件：`contracts/job-package.schema.json`（JSON Schema draft-07，版本 0.1.0）。两个 example 都是合成示例，不触发提交。

- `taskId + revision`：输入修订的稳定标识。
- `prompt`：意图、最终文本、来源与工作流。
- `references`：有序资产列表、角色、可移植路径与提交意图。
- `settings`：MJ 与 Banana 分支互斥。
- `confirmation`：人工确认时间、对应修订、提示词/参数/参考图三项确认。
- `photoshopContext`：可选的源 PS 上下文。

Schema 只校验形状。以下由运行时语义校验负责：确认修订相等；资产 ID 唯一；资产文件存在且哈希匹配；解包路径解析后仍在包目录内且非逃逸符号链接；抓取资产 ID 存在且源于该 PS 快照；蒙版 ID 指向蒙版资产；选区边界在画布内；角色/模型组合支持；参数范围、冲突、单图限制；确认动作是用户操作；Banana 提交时配置完整。通过 Schema 不代表已确认或可提交。

拟定的服务操作（名称是契约设计，**尚未实现**）：

| 操作 | 责任 |
|---|---|
| `createDraft / updateDraft` | 接收向导产物或手写输入；修改后递增修订并清空确认 |
| `confirmRevision` | 语义校验并封存用户确认的修订 |
| `prepareWebHandoff` | 产生可复制文本、素材包、官网设置清单；没有远端提交副作用 |
| `recordWebSubmission` | 用户声明官网提交，创建本地运行记录 |
| `importResults` | 按明确 task/revision/run 绑定图片，保留每张结果 |
| `submitBanana` | 使用配置引用提交已确认草稿，区分未知提交状态 |
| `placeResult / exportPackage` | 回传指定结果，或独立导出任务资料 |

相同确认请求应幂等；相同官网任务 ID 的重复导入需提示，而不是创建两次付费运行。接口使用本地鉴权、来源校验和有限请求体；不通过关闭 Prompt Wizard 原有 Origin 校验完成跨应用交接。

## 8. 验收与下一阶段

阶段 0 已完成：路线确定、源码盘点、流程定义、任务包 Schema、MJ 与 Banana 示例及结构校验。以下是后续实现验收条件，当前未宣称已通过：

契约校验记录（2026-11-12）：Schema 编译通过；3 个合法样例通过（含 0 值参数、未配置 Banana 草稿和完整确认结构）；13 个非法变体被拒绝，覆盖模式混用、凭证混入、路径逃逸、不完整确认、空白确认提示词、选区置入矛盾和非法日期。使用源码候选已有的 Ajv/Zod 只读校验，未安装或修改依赖。此检查不包含真实素材、官网操作、API 或 PS 联调。

| 编号 | 场景 | 必须满足 |
|---|---|---|
| MJ-01 | 文字、参数或参考图尚未确认 | 不产生“已提交”状态；可保存草稿或导出 |
| MJ-02 | 点击打开官网 | 浏览器打开失败可重试；本地仍不显示官网任务已创建 |
| MJ-03 | Seed=0、Chaos=0、Raw=true | 保留 0；按确认版本输出正确开关语法，无重复参数 |
| MJ-04 | 确认后更换参考图或参数 | 新修订必须重新确认；旧快照可追溯 |
| MJ-05 | 同时有两个任务并下载多张图 | 用户显式选择归属；不得按时间自动串单 |
| MJ-06 | 上传参考图用途不同 | 顺序和角色出现在交接清单中；仅分析素材不默认提交 |
| MJ-07 | 用户在官网改动了本地方案 | 导入时记录实际设置差异/未知；不能标记完全复现 |
| PS-01 | 等待期间切换活动文档 | 回到原文档或要求重绑定；不误置入 |
| PS-02 | 非矩形选区、画布尺寸变化 | 蒙版与变换正确，或明确要求重绑定 |
| OUT-01 | 任意一张候选图 | 可选择、导出、回传；不只处理数组第一张 |
| OUT-02 | 不连接任何生图服务 | 仍可生成/编辑并导出提示词及参考图包 |
| API-01 | Banana 未配置服务商 | 允许保存和导出，禁止发出真实请求 |
| API-02 | 提交响应丢失、图片下载失败 | 不盲目重提；下载失败单独重试 |
| MIG-01 | 合并 Prompt Wizard | 保留当前安装版功能与已有源码改动，不以 0.3.4 覆盖 0.4.1 |

阶段 1 建议先做：在本工作区建立可追踪的 MJStudio 开发副本；增加 MJ 官网任务状态与输入快照；修复队列/下载/临时目录问题；将 Banana 接口置于未配置状态。之后做交接界面和结果导入，再完善 PS 桥与 Prompt Wizard 联动。原 MJ 中转入口从目标产品中移除，旧代码仅作为迁移参考。

Banana 服务商、具体模型 ID 与 API 协议，以及 Prompt Wizard 最新源码位置/差异对齐，属于后续实施前必须补齐的信息；不影响阶段 0 完成和 MJ 官网协作开发。
