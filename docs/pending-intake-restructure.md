# 输入区重组方案（用户提案 · 待确认）

> 记录时间：0.4.9 之后。这是**用户提出的初步计划**，不是最终方案；
> 确认后并入正式执行计划。

## 用户的一级想法

把「输入信息」先做一次集成整理，**按区分块，每区给预设模板**：

### 区 1 · 约束区

- 约束里「不变的部分」
- 约束里「对提示词起作用的部分」
- 额外效果（可手写）

### 区 2 · 修图要求区

- 原始修图要求（语言随意）
- 重点覆盖：修改区域、修改内容、采用的模式、参考图可取部分的描述、效果描述预设

### 区 3 · 提示词格式

- **模式**：
  - 置入物品模式 —— 使用纯正语言做具体描述（消隐参考图来源）
  - 参考图模式 —— 使用「参考图1、2……」标记词，让参考图参与描述
- **语言**：中文 / 英文
  - 有些场景英文效果更好
  - MJ 模式默认英文

### 其它已确认

- 任务类型：**快捷模板 + 展开更多**，需要精修时可展开折叠区逐项改
- 「保持不变」：**固化成快捷标签**，点一下直接写进约束框

## 与当前实现对照（现存结构）

| 提案 | 现状 | 差距 |
|---|---|---|
| 约束区 | `constraints`（多行）+ `preserve`（多选 9 项）两个独立字段 | preserve 需要改成往 constraints 追加的 chips |
| 要求区 | `requirement`（多行）+ `taskType`(16)×`editRegion` + 8 个条件字段 + `referenceRole`(9) | 条件字段塌缩成「展开更多」；参考图职责收敛到逐张分工 |
| 格式区 | `referencePolicy`（2 选，仅在置入物体时出现）+ `outputMode`（3 选） | 新增「语言」；`referencePolicy` 提到格式区常驻 |
| 语言 | **不存在**。中文/英文由工作流写死（`complete-cn` / `mj-prompt-en`） | 需要新字段 + 契约分支 + 后处理语言适配 |
| 分区渲染 | 字段是一个扁平数组，按顺序平铺 | 需要 `group` 属性 + 分组渲染 |

## 可行性判断

### 可以做的（低风险）

1. **语言选择**：加一个 `promptLanguage` 字段，契约里换一句话，后处理按语言选清洗规则。
   注意：**分段标题保持中文**（`【正面提示词】` 这种），只用正文语言变化——
   否则前端的段落切分（`parseSections` 按 `【】`）会失效。
2. **保持不变 → chips 追加到约束框**：约束是自由文本，chips 只是快捷输入。
   需要保留「保持不变：」这个语义前缀，否则模型不知道这是锁定项。
3. **参考图职责收敛**：全局 `referenceRole` 与「逐张分工」功能重叠，
   建议以逐张分工为准，全局那份退成「整体用途」的可选补充。
4. **任务类型快捷模板**：模板 = 一组 `taskType` 值的预设，选了模板等价于勾选若干项。

### 需要额外设计的（中风险）

5. **三区分组渲染**：字段加 `group` 属性，接收阶段按区渲染。字段本身不变，
   编译提示词时仍按 `## 用户需求` 平铺 —— 也就是说**分区只影响界面，不影响模型输入**。
6. **展开更多**：条件字段（置物 5 项等）默认折叠。风险在于**折叠时模型信息变少**，
   需要在契约里给出兜底默认（例如「未指定层次时按中景处理」）。

### 有冲突需要解决的（需拍板）

7. **语言 vs 契约硬编码**：`complete-cn` 契约里写死了「一条完整中文 Prompt」，
   加语言开关后要把「中文」抽出来变成变量，否则两句指令自相矛盾。
8. **语言 vs 后处理清洗**：`Du()` 消隐规则匹配的是中文词（参考图、素材图、与某图一致），
   英文输出时需要一套英文等价规则（reference image / as seen in / same as the reference）。
   否则「置入物品模式 + 英文」会把参考图来源泄漏进提示词。
9. **MJ 线**：已经是英文正文，语言开关对它应该是**只读**（默认英文、不可改），
   避免出现「MJ 提示词用中文写」这种无效组合。

## 待确认问题（见对话）

1. 英文模式下，段落标题是否仍用中文
2. 「参考图可取部分」放要求区还是格式区
3. 「额外效果」放约束区还是要求区
4. 语言开关是否只作用于 prompt 正文（channel / checklist 保持中文）
